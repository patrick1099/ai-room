# ai-room Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local Windows-first CLI that lets one interactive Codex session and one interactive Claude Code session reliably consult each other, while restricting the advisor to exact documentation paths and reminding the user to compact only at a recorded safe checkpoint.

**Architecture:** A Python 3.11+ package exposes six `ai-room` commands over a room-scoped SQLite database in `%LOCALAPPDATA%/ai-room`. A service layer owns queue and task state; adapters read each tool's real session token usage; a content-hash guard blocks advisor replies after out-of-scope file changes. A shared agent skill defines role behavior, and an idempotent installer places that skill plus the minimal Claude `SessionStart` hook without replacing existing settings.

**Tech Stack:** Python 3.11+, standard-library runtime (`argparse`, `sqlite3`, `json`, `pathlib`, `hashlib`, `subprocess`, `threading`), pytest for tests, PowerShell for Windows acceptance commands.

## Global Constraints

- Before editing Python, the implementation agent must read and follow `vibe-scripts` and `superpowers:test-driven-development`.
- Runtime code uses the Python standard library only. Keep `pytest` in the optional `dev` dependency group.
- Preserve the public command surface: `join`, `wait`, `send`, `reply`, `status`, `leave`. Installation is invoked separately with `python -m ai_room.install`.
- The advisor may answer technical decisions and modify only exact paths in `writable_docs`. It must never modify source code, run tests/builds/deployments, or perform real operations for the primary AI.
- Every state-changing storage operation is a short transaction. Configure SQLite WAL and a 5-second busy timeout.
- `wait` polls every 500 ms, writes a heartbeat every 5 seconds, and reports a waiter stale after 15 seconds.
- Cancellation must never acknowledge a message. Reply creation, request acknowledgement, terminal state, and next-task activation must commit atomically.
- Workspace violations block `reply`, list changed paths, and never restore or delete user files.
- Token parsing failure returns `unknown`; never estimate context from transcript size or cumulative usage.
- Automatic compaction is forbidden. `COMPACT_READY` only tells the user when manual `/compact` is safe.
- Use UTF-8 for tool-owned files and JSON, `ensure_ascii=False` for user-visible JSON, and tests containing Chinese text and Windows-style paths.
- Run the named focused test after each implementation step, then the complete suite before each task commit. Do not commit a red suite.
- Use the repository's configured noreply Git identity. Before every public push, scan tracked files for tokens, credentials, private email addresses, and machine-specific absolute home paths.

- [ ] **Step 2: Implement schema version 1 and JSON boundaries**

Create tables `schema_meta`, `rooms`, `members`, `tasks`, `messages`, `context_samples`, and
`quarantined_messages`. Enforce foreign keys, a unique `(room_id, idempotency_key)` on tasks, and a unique
`(room_id, idempotency_key)` on messages plus `(task_id, sequence)` for message order. Add a partial unique index
that permits only one terminal reply per task. Nonterminal `checkpoint_needed` replies and checkpoint follow-ups
may repeat in later rounds. Use JSON only for exact path lists, snapshots, context metadata, and structured
payloads; validate decoded types before returning them. Generate opaque UUID4 strings for externally visible task
and message IDs; use an internal integer sequence only for FIFO ordering.

Opening a new database must execute:

```sql
PRAGMA journal_mode=WAL;
PRAGMA busy_timeout=5000;
PRAGMA foreign_keys=ON;
```

If `schema_version` is not `1`, raise `SchemaVersionError` and do not write, rebuild, rename, or delete the file. If
SQLite reports a corrupt or non-database file, raise `DatabaseOpenError` with the path redacted to its final name.

- [ ] **Step 3: Implement atomic activation, claim leases, and reply transitions**

Use `BEGIN IMMEDIATE` for mutations. `enqueue_task` activates the oldest task only when no task in that room is
`working` or `waiting_checkpoint`. `claim_next_message` records `delivered_at`, a random lease token, and
`lease_expires_at`; an expired unacknowledged request or reply is deliverable again. Store `round_no` on a task so
each checkpoint cycle has its own request/reply pair. `reply` must:

1. verify recipient and current state;
2. return the existing reply when the same task/round/outcome/body repeats;
3. reject conflicting second replies;
4. acknowledge the request and create the reply in the same transaction;
5. set `WAITING_CHECKPOINT` for `CHECKPOINT_NEEDED`, otherwise set the matching terminal state;
6. activate the next queued task only after a terminal outcome.

Expose structured exceptions: `PeerNotJoinedError`, `TaskConflictError`, `SchemaVersionError`,
`MalformedMessageError`, `DatabaseOpenError`, and `DatabaseBusyError`. Quarantining a malformed request must mark
its task blocked with an internal corruption reason and activate the next queued task in the same transaction.

    primary, advisor = service_pair
    primary.send(task_request)
    cancelled = threading.Event()
    cancelled.set()
    assert advisor.wait(cancel_event=cancelled) is None
    delivery = advisor.wait(cancel_event=threading.Event())
    assert delivery.task_id == primary.status().active_task.task_id


def test_wait_updates_heartbeat_while_blocked(service_pair, fake_clock) -> None:

- [ ] **Step 2: Implement the service loop with injected timing**

The default constructor uses `poll_seconds=0.5`, `heartbeat_seconds=5.0`, and `stale_seconds=15.0`. The wait loop
must check cancellation before claiming, refresh heartbeat on schedule, claim a message, and return immediately on
delivery. A `finally` block clears only the current waiter's PID/token; it does not leave the room or acknowledge a
task.

Use `threading.Event.wait(timeout)` instead of `time.sleep` so cancellation reacts promptly. Do not catch
`KeyboardInterrupt` in the service layer; the CLI maps it to exit code 130. On entry, a new `wait`, `send`, or
`reply` from the same registered session explicitly acknowledges that session's previously delivered informational
reply. A delivered request is acknowledged only by `reply`. Thus a process that dies after output but before the AI
issues its next ai-room command receives the message again after the lease expires.

- [ ] **Step 3: Implement send/reply/status/leave orchestration**

`send` must reject sending to self and reject a peer that has never joined. It may queue to a joined peer that is
not currently waiting. `status` distinguishes `never_joined`, `joined_not_waiting`, and `waiting`; stale heartbeat
always resolves to `joined_not_waiting`. `leave` clears online/wait state only and preserves rooms, tasks and
messages.

## Task 6: Safe Compaction Policy and Checkpoint Conversation

**Interfaces:**

- `evaluate_compaction(sample, previous, checkpoint_fingerprint) -> CompactionAction`

- [ ] **Step 1: Write threshold and repeat-suppression tests**

Cover unknown, `149999`, `150000`, `200000`, `200001`, a repeat with `9999` new tokens, a repeat with `10000`
new tokens, unchanged paths/content, changed checkpoint content, context drop after compaction, and no joined peer.

```python
@pytest.mark.parametrize(
    ("tokens", "expected"),
    [
        (None, CompactionAction.NONE),
        (149_999, CompactionAction.NONE),
        (150_000, CompactionAction.REQUEST_CHECK),
        (200_000, CompactionAction.REQUEST_CHECK),
        (200_001, CompactionAction.URGENT_CHECK),
    ],
)
def test_thresholds(tokens, expected) -> None:
    assert evaluate_compaction(sample(tokens), None, "checkpoint-a") is expected


def test_same_checkpoint_requires_ten_thousand_more_tokens() -> None:
    previous = previous_check(tokens=155_000, fingerprint="same")
    assert evaluate_compaction(sample(164_999), previous, "same") is CompactionAction.NONE
    assert evaluate_compaction(sample(165_000), previous, "same") is CompactionAction.REQUEST_CHECK
```

- [ ] **Step 2: Implement the pure policy**

Define `NONE`, `REQUEST_CHECK`, and `URGENT_CHECK`. Unknown samples and samples below 150k return `NONE`.
150k through 200k return `REQUEST_CHECK`; above 200k returns `URGENT_CHECK`. Suppress a repeat only when both
conditions hold: token growth is less than 10k and the checkpoint fingerprint is unchanged. A sample lower than
the last checked sample clears pending-compaction state as evidence that compaction occurred.

Checkpoint fingerprint is SHA-256 over sorted exact relative paths plus each current content hash. Missing exact
paths are encoded as `MISSING`; do not include directory-wide state.

- [ ] **Step 3: Integrate context-check creation and continuation**

On entry, `service.wait` first acknowledges the caller's prior informational delivery and claims any already pending
inbound message. Only when no inbound message exists does it sample its own adapter before blocking. When policy
requests a check, enqueue one idempotent `context_check` to the peer containing agent name, input tokens or unknown,
context-window value or unknown, sample source, checkpoint docs, and next-entry text. If no peer has joined, return
a structured actionable error instead of pretending the check happened. This ordering prevents a context reminder
from delaying an advisor task that is already waiting for the caller.

`CHECKPOINT_NEEDED` sets the task to `waiting_checkpoint` and delivers the advisor's missing-record list to the
primary. A repeated `--checkpoint EXACT_PATH` option on `wait` validates those paths, recomputes the fingerprint,
increments `round_no`, adds a follow-up message to the same task, returns it to `working`, and then waits. The next
advisor claim captures a fresh round baseline after the primary's checkpoint edits. `COMPACT_READY` closes the task
and includes the tool name, token count, checkpoint documents, and recovery entry. It never executes `/compact`.
